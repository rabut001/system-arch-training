# 問題のチェック

あとで戻って見たい問に印を付ける。正誤とは別の状態で、回ごとの `localStorage` に残す。

## 現在地

完了。利用者のレビューは問題なしである。`checklist.json` の16項目は、狭い幅と広い幅の両方で確認済みである。

## 目的

解きながら、あとで戻って確認したい問をその場で印づけておく。印を見た番号から、その問へ戻れるようにする。

## 決めたこと

- チェックは問ごとである。未選択、選択済みで未確認、確認済みのどれでも付け外しできる。付け外しは、選んだ肢も正誤も変えない。確認済みの選択は、これまでどおり固定する。
- チェックボックスは、問題画像を表示している領域の中、画像の上の右端に置く。番号の列の枠には置かない。
- チェックボックスは問題画像の幅を削らず、文字や図にも重ねない。
- 問題画像は、この部分だけ縦にスクロールする。スクロールバーは出さない。チェックボックスは、そのスクロールの外、画像の上の右端に置く。画像をスクロールしても、その位置に残る。
- ア〜エから出典までの下部も、はみ出した分はそこだけ縦にスクロールする。スクロールバーは出さない。
- 別の問へ移ったときは、問題画像のスクロールと、下部のスクロールを先頭に戻す。
- チェックした問は、画面上部の問題番号の右上に太いチェックを付ける。番号の下にある正誤や未確認の印も、これまでどおり出す。二つの印は同時に出てよい。
- 保存は、いまの進捗と同じ `localStorage` のキーに足す。一覧へ戻って同じ回を開き直しても、再読み込みしても残る。ほかの回には影響しない。
- 「回答をすべてクリア」は、その回の解答と、今開いている問番号を消して問1へ戻す。チェックは残す。チェックを外す操作は、その問のチェックボックスだけである。
- 一括採点はチェックを変えない。一覧にはチェックの数を出さない。

## 画面

演習画面は回ごとに作り分けない。チェックの操作も、同じ画面に足す。

問題画像の領域は、この部分だけ縦にスクロールする。スクロールバーは出さない。チェックボックスは、そのスクロールの外、画像の上の右端に置く。画像をスクロールしても、その位置に残る。問題画像は、その欄の幅を使う。ア〜エから出典までの下部も、はみ出した分はそこだけ縦にスクロールし、スクロールバーは出さない。ページ全体は横にはみ出さない。幅が広いときも、本文を画面いっぱいに引き伸ばさない。別の問へ移ったときは、問題画像のスクロールと、下部のスクロールを先頭に戻す。

チェックボックスに「チェック」という文言は付けない。当たり判定は、一覧へ戻る、ア〜エ、結果を確認と同じく、指で押せる大きさにする。スクリーンリーダーには「問Nをチェック」と読ませる。チェックの有無は、そのチェックボックスの状態で分かる。

番号のチェックは、線の太いチェックとする。文字の `✓` は使わない。番号ボタンの文字として読ませず、視覚だけの印にする。今開いている問の強調色の上でも読める色にする。番号の下の `○` `×` `●` とは、形と位置で区別する。下の未確認の印が `●` なので、右上には `●` を使わない。番号ボタンの当たり判定は、これまでどおり指で押せる大きさにする。狭い幅でも、番号の列は折り返し、ページは横にはみ出さない。

番号ボタンの読み上げは、いまの状態にチェックの有無を足す。

| 例 | 読み上げ |
| --- | --- |
| 問3をチェックし、未選択 | 問3、チェック済み、未選択 |
| 問3をチェックし、イを選んで未確認 | 問3、チェック済み、選択済み、未確認 |
| 問3をチェックし、確認済みで正解 | 問3、チェック済み、正解 |
| 問3はチェックせず、確認済みで誤答 | 問3、誤答 |

チェックの付け外しで、開いている問番号は変えない。前へ、次へ、番号の移動でも、移動先のチェックを表示する。

「回答をすべてクリア」の確認文は、チェックが残ることを書く。見出しは「この回の解答を消します」のままとする。本文は次のとおり。

> {回の title}の確認済みの解答と、まだ確認していない選択を消して、問1に戻ります。チェックはそのまま残します。

中止すれば、解答もチェックも、開いている問も変えない。

## 保存

キーはいまどおり回の `id` ごとに `sa-am2:{id}` とする。値は次の形にする。

```json
{
  "currentNo": 3,
  "answers": {
    "1": { "choice": "イ", "confirmed": true }
  },
  "checked": [3, 14]
}
```

`checked` は、チェックした問番号の配列である。昇順で重複なく保存する。

読み込みでは、いまの `currentNo` と `answers` の検証を維持する。加えて次を行う。

- `checked` が無い、または配列でないときは、空にする。
- 整数でない値、その回に無い問番号は捨てる。
- 残った番号の重複は一つにする。

`checked` を持たない既存の保存は、解答と開いている問番号を維持したまま読み、チェックは空にする。演習画面を開くと今の形で保存し直すので、その時点から `checked` が空配列で入る。解答は残る。

クリアは、このキーを消さない。`answers` を空にし、`currentNo` を 1 にし、`checked` は読み込んだ内容のまま、同じキーへ保存する。`checked` が空のときも、空配列のまま保存する。結果は、問1の未選択で、チェックは残った分だけ付く。

## 今回の仕様に含めないもの

- チェックした問だけを出題する画面、番号の絞り込み、チェックの件数の表示。戻り先は、番号の右上の太いチェックから選ぶ。
- チェックをまとめて外す操作。外すのは、その問のチェックボックスだけである。
- 一覧画面へのチェック数。一覧はこれまでどおり、回の `title` だけを出す。
- 問題 JSON、問題画像、公開パスの変更。

## 手順

1. `AGENTS.md` の演習画面、問の状態、進捗の保存を、この文書の決めたことに合わせる。
2. `progress.ts` に `checked` を足す。既存の保存が読めることを、`checked` が無い値で確認する。
3. 演習画面にチェックボックスと番号の太いチェックを足す。クリアはチェックを残す。
4. スタイルを足す。チェックボックスは問題画像の領域の中、画像の上の右端に置き、画像の幅は削らない。問題画像と、ア〜エから出典までの下部は、それぞれはみ出した分だけ縦にスクロールし、スクロールバーは出さない。番号の右上の印、指で押せる大きさを満たす。
5. 開発サーバを起動し、利用者のレビューを受ける。`checklist.json` の確認には入らない。
6. レビューで問題なしとなったあと、`checklist.json` の項目を開発サーバで確認する。見た結果は、その項目のコメントに残す。

## 確認

利用者のレビューで問題なしとなったあと、実装後の確認を `checklist.json` で管理する。開発サーバで演習画面を開き、項目ごとに結果を残す。このファイルは `specs/` に置く。サイトには載せない。

各項目は、確認する内容、幅、状態、コメントを持つ。幅は次の二つで、同じ内容を両方で確認する。

| 幅 | 画面 |
| --- | --- |
| `狭い幅` | 幅 390px 前後の携帯表示 |
| `広い幅` | 幅 1280px 前後の PC 表示 |

状態は次のとおり。

| 状態 | 意味 |
| --- | --- |
| `未着手` | まだ確認していない |
| `要見直し` | 確認し、内容を満たさなかった |
| `確認済み` | 確認し、内容を満たした |

コメントは追記する。過去の文は消さない。要素は `role`（`確認`）と `text` である。

`確認済み` にするときは、画面で見た結果を `text` に書く。見た回と問番号が分かるようにする。状態だけを変えて、コメントを空のままにしない。この文が、その項目を OK とした証拠である。

`要見直し` にするときは、満たさなかった点を `text` に書く。直したあとは、同じ項目を確認し直す。直し前のコメントは残し、満たしたときの結果を新しいコメントとして足してから `確認済み` にする。

すべての項目が `確認済み` になってから、進め方のこの案件を「完了」にする。
