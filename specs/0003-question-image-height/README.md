# 問題画像の表示の高さ

チェック行と、番号を縦に伸ばした余白で短くなった、問題画像の表示に使う縦の長さを、足す前と同じ程度に戻す。

## 現在地

完了。利用者のレビューは問題なしである。`checklist.json` の8項目は、狭い幅と広い幅の両方で確認済みである。

`specs/0002-question-check/` は完了のままとする。チェックの付け外しと保存は、あの案件の仕様のままである。この案件で変えたのは、番号の印の位置と並び、選択済みで未確認の黒丸を出さないこと、開いている問の反転、確認済み番号の薄い色である。

## 目的

演習画面で、問題画像を読むための縦の長さを、チェック行と、番号を縦に伸ばす余白を置く前と同じ程度に戻す。

## 原因

演習画面は高さ `100dvh` の縦積みである。問題画像の領域の中で、チェック行が画像のスクロールの上に並ぶ。チェック行が占める高さは、当たり判定 `2.75rem` と、その下の間隔 `0.35rem` を合わせた `3.1rem` である。この分だけ、問題画像を表示できる縦の長さが短くなっている。

画面の高さはビューポートのままなので、チェック行の分は、ア〜エから出典までの下部から取る。

番号ボタンは、右上のチェックのための上余白 `1rem` と、下の印のための下余白 `0.7rem` で、高さが約 `3.2rem` になっている。指で押せる最小は `2.75rem` なので、印を数字の下の一列にまとめ、幅も高さも `2.75rem` に戻す。狭い幅では番号がおよそ 4 段あり、戻る縦は約 `1.8rem` である。広い幅ではおよそ 2 段で、約 `0.9rem` である。この分は上部が縮むので、問題画像の表示へそのまま戻る。一覧へ戻るボタンと、回の `title` の高さは変えない。

## 決めたこと

- 問題画像のスクロール領域の表示高さを、チェック行を置く前と比べて `3.1rem` 戻す。戻す相手は下部である。
- 下部が最大高さに達しているときも、内容がその上限より短いときも、下部の占有を `3.1rem` 減らす。いまの最大高さ `45vh` は `calc(45vh - 3.1rem)` にする。内容側は、上下の余白と、並んでいる要素のあいだの間隔を、合わせて `3.1rem` 減らす。
- ボタンとリンクの最小の大きさは `2.75rem` のままとする。狭くするのは余白と間隔である。
- 結果を確認する前でも、解説を出したあとでも、同じ `3.1rem` を下部から取る。
- チェックボックスは、問題画像を表示している領域の中、画像の上の右端に置く。問題画像の幅は削らず、文字や図には重ねない。画像を縦にスクロールしても、その位置に残る。当たり判定は `2.75rem` のままとする。
- 狭い幅と広い幅の両方で戻す。ページ全体は横にはみ出さない。問題画像と下部は、はみ出した分だけそれぞれの領域で縦にスクロールし、スクロールバーは出さない。
- 別の問へ移ったときは、問題画像のスクロールと、下部のスクロールを先頭に戻す。
- 番号の太いチェックと、○ × は、数字の下に横一列で置く。左が ○ ×、右が太いチェックである。数字の左右には置かない。チェックは太い線のままとし、文字の `✓` は使わない。○ × とは形で区別する。太いチェックは、正解、誤答、未確認、未選択では黒で描く。今開いている問では、反転に合わせて白で描く。正誤の印が無いときは、太いチェックは数字の下の中央に置く。選択済みで未確認の問は、黒丸を出さない。開いていないときは、その番号の枠を濃い金にする。読み上げは「選択済み、未確認」のままとする。
- 結果を確認した番号は、ボタン自体に薄い色を付ける。正解は薄い緑、誤答は薄い赤である。今開いている問は、この薄い色ではなく、濃い青地に白の反転にする。数字、○ ×、太いチェックも白にする。
- 番号の幅と高さは `2.75rem` にする。チェックだけ、正誤の印だけ、両方、どれも無い、のどれでも同じ大きさにする。狭い幅での折り返しの段数は増やさない。ページは横にはみ出さない。
- 番号の読み上げは、問題のチェックの仕様のままとする。太いチェックと ○ × は、ボタンの文字としては読ませない。
- 画面の高さが足りず、下部が内容の高さより縮んでいるときは、余白と最大高さの変更だけでは問題画像へ `3.1rem` が戻りきらない。そのときは下部の高さを、問題画像の表示高さが戻る位置まで縮める。戻りきっているときは、下部の高さは内容と最大高さに任せる。

下部の余白と間隔は、次の値にする。減る量の合計が `3.1rem` になる。

| 対象 | いま | 修正後 | 減る量 |
| --- | --- | --- | --- |
| 下部の上の余白 | `0.75rem` | `0.25rem` | `0.5rem` |
| 下部の下の余白 | `1rem` | `0.4rem` | `0.6rem` |
| 結果を確認、または解説ブロックの上の間隔 | `0.75rem` | `0.35rem` | `0.4rem` |
| 前へ・次への上の間隔 | `0.75rem` | `0.35rem` | `0.4rem` |
| 一括採点の上の間隔 | `0.75rem` | `0.35rem` | `0.4rem` |
| 回答をすべてクリアの上の間隔 | `0.75rem` | `0.35rem` | `0.4rem` |
| 出典の上の間隔 | `0.75rem` | `0.35rem` | `0.4rem` |

左右の余白は `1rem` のままとする。結果を確認と解説ブロックは同時には出ないので、上の間隔はどちらか一方だけが効く。

## 手順

1. `AGENTS.md` の演習画面が、この文書の決めたことと一致していることを確認する。進め方のこの案件を「着手」にする。
2. `web/src/Practice.tsx` と `web/src/index.css` で、番号の太いチェックと ○ × を数字の下の横一列にする。左が ○ ×、右が太いチェックである。正誤の印が無いときは、太いチェックは中央に置く。選択済みで未確認の黒丸は出さない。開いていない未確認の番号は、枠を濃い金にする。開いている問は濃い青地に白で反転し、確認済みで開いていない番号は、正解なら薄い緑、誤答なら薄い赤にする。番号の幅と高さは `2.75rem` にする。画面の高さが足りないときは、下部の高さを、問題画像の表示高さが戻る位置まで縮める。チェック行の大きさと位置は変えない。
3. `web/src/index.css` で、下部の最大高さを `calc(45vh - 3.1rem)` にする。余白と間隔を、決めたことの表の値にする。
4. 開発サーバを起動し、問題画像の表示高さが戻っていることを測る。修正後の `.image-scroll` の表示高さは、修正前より、チェック行の外側の高さ `3.1rem` と、`.numbers` が縮んだ高さを足した分だけ高い。差は 4px 以内とする。番号ボタンの表示幅と表示高さは `2.75rem`（16px 基準で 44px、枠を含めて数 px の差まで）とする。幅 `390px` 前後では番号が 4 段、幅 `1280px` 前後では 2 段のままとする。結果確認前と、解説を出したあとの両方を測る。縦に長い問で、画像のスクロール、チェックボックスの位置、番号の印の並びを見る。
5. 開発サーバを起動したまま、利用者のレビューを受ける。`checklist.json` の確認には入らない。
6. レビューで問題なしとなったあと、`checklist.json` の項目を開発サーバで確認する。見た結果は、その項目のコメントに残す。

レビューで、下部の間隔が窮屈だと指摘されたときは、ボタンとリンクの最小の大きさは `2.75rem` のまま、余白と間隔の取り方を直す。問題画像へ戻す `3.1rem` は維持する。直したあとは、もう一度レビューを受ける。

## 確認

利用者のレビューで問題なしとなったあと、実装後の確認を `checklist.json` で管理する。開発サーバで演習画面を開き、項目ごとに結果を残す。このファイルは `specs/` に置く。サイトには載せない。

各項目は、確認する内容、幅、状態、コメントを持つ。幅は次の二つで、同じ内容を両方で確認する。

| 幅 | 画面 |
| --- | --- |
| `狭い幅` | 幅 390px 前後の携帯表示 |
| `広い幅` | 幅 1280px 前後の PC 表示 |

状態は次のとおり。

| 状態 | 意味 |
| --- | --- |
| `未着手` | まだ確認していない |
| `要見直し` | 確認し、内容を満たさなかった |
| `確認済み` | 確認し、内容を満たした |

コメントは追記する。過去の文は消さない。要素は `role`（`確認`）と `text` である。

`確認済み` にするときは、画面で見た結果を `text` に書く。見た回と問番号、測った表示高さが分かるようにする。状態だけを変えて、コメントを空のままにしない。この文が、その項目を OK とした証拠である。

`要見直し` にするときは、満たさなかった点を `text` に書く。直したあとは、同じ項目を確認し直す。直し前のコメントは残し、満たしたときの結果を新しいコメントとして足してから `確認済み` にする。

すべての項目が `確認済み` になってから、進め方のこの案件を「完了」にする。
