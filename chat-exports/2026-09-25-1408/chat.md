## アシスタント

静的な演習サイトにして、問題本文はPDFのページをそのまま表示し、解答だけをデータ化する進め方がよいです。GitHub Pages に載せる前提で、サーバは置きません。

## 資料から分かったこと

`exams/` に平成21年度秋期から令和7年度春期まで、令和2年度を除く **16回** 分があります。午前Ⅱは各回25問なので、全部で約400問です。午前Ⅱの問題冊子と解答例だけなら合計およそ 28MB で、Pages に載せられます。

問題冊子（`am2-mondai.pdf`）は図や表が多く、ページ画像が本体です。解答例（`am2-kaitou.pdf`）はテキストですが、IPA の PDF はコピー制限付きで暗号化されています。問題文を機械的にテキスト化して選択肢カードにするより、冊子のページを見せて「ア〜エ」を選ばせる方が、図の欠落や誤認識を避けられます。

## アプリの形

1回分を選んで、冊子のページをめくりながら解きます。各ページに載っている問題番号ごとにア・イ・ウ・エを選び、送り終わったら正誤と得点を出します。午前Ⅱの合格ラインは 60 点（25問中 15問）なので、その基準も表示します。途中経過と正誤はブラウザの `localStorage` に保存し、同じ端末で続きから再開できるようにします。

解説の自動生成や分野タグは後回しにします。公式の解答例以外の文章を足すと、出典の扱いが重くなるためです。

## 技術

| 役割 | 選び方 |
| --- | --- |
| 画面 | Vite。ビルド結果を GitHub Pages に出す |
| 問題の表示 | PDF.js で `am2-mondai.pdf` をページ単位に描画する |
| 解答 | 解答 PDF から抜き出した JSON |
| 画面遷移 | ハッシュルーティング。Pages の 404 対策が不要になる |
| 公開 | GitHub Actions で `main` への push をビルドし、Pages に載せる |

画面は `web/`、抽出スクリプトは `scripts/` に置きます。生成した解答 JSON はリポジトリにコミットし、実行のたびに PDF を読み直さなくてよいようにします。

## 段階

1. **1回分で通り道を確認する。** 令和7年度春期だけで、解答 PDF の復号と「問1＝イ」形式への変換、問題 PDF のページ表示ができるかを見ます。ここでレイアウトのばらつき（1ページに何問あるか）も確定します。
2. **16回分の解答 JSON を作る。** 年度・問題番号・正解・出典 URL を1ファイルにまとめ、抜き出し結果を目視で数件照合します。
3. **最小の演習画面を作る。** 回の選択、ページ表示、ア〜エの回答、採点、合格ライン、`localStorage` までを含めます。ランダム出題や苦手の復習は入れません。
4. **GitHub Pages に公開する。** Actions の workflow、`base` パス、出典表記（IPA の過去問題ページ）を入れます。
5. **復習を足す。** 間違えた問題だけ、年度をまたいだランダム、正答率の表示です。分野分類が必要になった時点で、問題ごとに手でタグを付けます。

最初の実装は手順 1 と 2 です。解答の抜き出しが安定してから画面に入ります。この順で進めてよければ、令和7年度春期の1回分から着手します。

## 4. データの形

試験回ごとに、次だけを持たせます。

- 回の ID（例: `2025-r07-haru`）と表示名
- 問題 PDF のパス
- 出典 URL
- 問ごとの番号、正解（ア〜エ）、ページ番号

解説文や分野タグは持ちません。解答例 PDF はサイトには出さず、抽出後の JSON だけをアプリが読みます。静的サイトなので、JSON を開けば正解は見えます。個人の勉強用として、その前提で進めます。

## 5. 公開の仕方

公開リポジトリの GitHub Pages にします。無料で使えるのは公開リポジトリ側です。サイトのパスはリポジトリ名に合わせ、Vite の `base` を `/system-arch-training/` にします。

サイトに載せるのは、アプリのビルド結果、午前Ⅱの問題 PDF、解答 JSON です。午後問題や解答 PDF はリポジトリに残し、Pages の成果物には含めません。

## 6. 進捗の保存場所

ブラウザの `localStorage` に、回ごとの選択と採点結果だけを保存します。アカウントや端末間の同期はしません。
